# dnspcap — DNS over PCAP (Go, macOS)

Небольшая консольная утилита, которая говорит с DNS-серверами напрямую через
libpcap, минуя системный сетевой стек. Ethernet-, IPv4-, UDP- и DNS-заголовки
собираются и разбираются руками — единственная сетевая зависимость это
низкоуровневые pcap-биндинги (`github.com/google/gopacket/pcap`).

Позволяет посмотреть, как реально устроен DNS: разницу между итеративным
ответом корневого сервера (referral → NS + glue) и рекурсивным ответом
провайдерского резолвера, двухшаговый поиск MX → A и захват всех DNS-пакетов
в PROMISCUOUS-режиме.

## Требования

- macOS (проверено на Apple Silicon / darwin 25). Linux с небольшими правками
  вокруг BPF тоже должен работать.
- Go 1.21+ (`brew install go`).
- libpcap (входит в macOS; установите Wireshark — он настроит правила
  доступа к BPF-устройствам через группу `access_bpf`).

## Быстрый старт

```bash
# 1. сгенерировать конфиг под вашу сеть
./probe.sh > config.txt   # автодетект; пробегитесь глазами по значениям

# 2. собрать
go build -o dnspcap

# 3. запустить
./dnspcap
```

Если вы не в группе `access_bpf` — потребуется `sudo ./dnspcap`.

После запуска программа выведет список команд и приглашение `>`.

## Команды

| Команда          | Что делает                                           |
|------------------|------------------------------------------------------|
| `help`           | Повторно показать меню                               |
| `cfg`            | Показать загруженную конфигурацию                    |
| `sniff`          | PROMISCUOUS-захват всех DNS-пакетов (Ctrl+C — выход) |
| `mx <domain>`    | MX → A (двухшаговый поиск), вывод `D -> IP`          |
| `root <domain>`  | A-запрос напрямую к корневому серверу (RD=0)         |
| `isp <domain>`   | A-запрос к DNS провайдера (RD=1)                     |
| `probe`          | Список pcap-видимых интерфейсов (диагностика)        |
| `quit`           | Выход                                                |

## Структура проекта

```
main.go                         — консольное меню, точка входа
config.txt                      — IP/MAC/DNS параметры (не в коде)
probe.sh                        — автодетект значений для config.txt на macOS
internal/l234/ethernet.go       — Ethernet (14 байт)
internal/l234/ipv4.go           — IPv4 + Internet Checksum
internal/l234/udp.go            — UDP + псевдо-заголовок для контрольной суммы
internal/dnsmsg/types.go        — константы (типы RR, классы, RCODE)
internal/dnsmsg/builder.go      — формирование DNS-запроса
internal/dnsmsg/parser.go       — разбор DNS-ответа (+ компрессия имён)
internal/netio/netio.go         — тонкая обёртка вокруг libpcap
internal/config/config.go       — загрузка config.txt
internal/tasks/common.go        — общий send+recv помощник
internal/tasks/task1_sniffer.go — команда sniff
internal/tasks/task2_mx.go      — команда mx
internal/tasks/task3_direct.go  — команды root / isp
```

## Примечания по реализации

- RD=1 используется только при обращении к резолверу провайдера.
  К корневому серверу запрос уходит с RD=0 (корневые серверы не выполняют
  рекурсию; ответ — referral с NS в AUTHORITY и A/AAAA glue в ADDITIONAL).
- Исходящий UDP-порт — случайный из эфемерного диапазона, transaction ID
  тоже случайный; BPF-фильтр на приём сужен до конкретного сервера и порта,
  поэтому «чужие» DNS-запросы с системы не попадают в ответ.
- Ядро macOS увидит UDP-ответ на порт, никем не привязанный, и может отправить
  ICMP Port Unreachable обратно серверу. Это не мешает нам — ответ уже
  захвачен libpcap до того, как ядро среагировало.
